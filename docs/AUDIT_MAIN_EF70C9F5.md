# OmniForge main audit

**Audited revision** `ef70c9f5bcee56702944db0414dc6b61be5a3724` · **Date** 25 November 2026 (Tehran)

The Linux developer workflow runs and the packaged Workbench passed a real browser workflow. The production image failed to start when built from the environment’s restrictive checkout, and an explicit entrypoint mode resolved that failure in a temporary build. Several result fields still overstate what their underlying algorithms established. The highest-priority repairs are AutoML evaluation and budget enforcement, optimization status, deterministic pipeline replay, and statistical result labeling.

The audit anchored to the remote `main` tip in a separate checkout. The manifest covers all 391 tracked files. It records SHA-256 and byte sizes for source, generated bundles, dependencies, fixtures, CI, documentation, and release tooling. Manual review focused on public claims, shared engines, entry points, and the code paths behind the findings. Complete line-by-line review of the approximately 75,000 lines under the Python package and frontend source, exhaustive backend execution, and independent validation in every industry domain remain open.

## Findings and repairs

### P1 · Repair decision and execution contracts

| ID | Evidence and consequence | Fix and acceptance test |
|---|---|---|
| A01 | **AutoML selects and scores on the same holdout.** `automl/pipeline_search.py:329,379,487,573,596,610–617` scores candidates on `X_va`, uses those scores to choose tuning targets and ensemble members, then reports the champion's score on those rows. Inner tuning itself uses training folds. The selected validation score is optimistic as an estimate of out-of-sample champion performance. The refitted artifact also carries a score measured on an earlier fit. | Select families, tune, and form ensembles within development data. Evaluate the frozen selection on an untouched, split-aware test partition. Keep validation, test and refit provenance separate. Add a regression that traces row IDs through selection and evaluation and a shuffled-label test across seeds. |
| A02 | **Latency units are off by 1,000× and budget enforcement is incomplete.** `automl/pipeline_search.py:176–196,377–391,465–482,565–609` labels elapsed milliseconds per row as milliseconds per 1,000 rows. With a mocked 100 ms measurement over 100 rows, it returns 1 where the stated normalization requires 1,000. Deep, tuned and ensemble rows use different paths without the same budget checks. Candidates with missing measurements can remain on the Pareto frontier. | Correct conversion and API units. Apply a common measurement/admission path to all eligible candidates, distinguish missing readings, and specify whether limits are per candidate or per run. Add fixed-clock threshold tests, then check every champion family under hard limits. |
| A03 | **The deployable AutoML pipeline can implement a different model.** `automl/pipeline_search.py:610–634,690–697` exports a fresh sklearn pipeline. Unsupported winning families are substituted with random forest or ridge. Even shared family names can use different preprocessing or estimator defaults. Predictions and metrics can diverge from the champion. This is a confirmed source-level contract mismatch. | Serialize the trained winning estimator together with its preprocessing, or return a typed export-unavailable result for unsupported champions. Verify probability or regression prediction parity after reload for classical, tuned, ensemble and deep winners. |
| A04 | **Optimization claims are stronger than the solver guarantees.** `optimization/solvers.py:348–428` marks the Clarke–Wright + 2-opt result `optimal=True`. On a seeded eight-point Euclidean case the returned length is 2.5472 and enumeration finds 2.484346. At lines 430–451 an SLSQP solution starting at 1 is also marked optimal despite attaining 0.389442 on a nonconvex objective with a feasible value of −0.4. | Separate feasible solution, local convergence, global certificate and verified gap. Preserve solver diagnostics and validate feasibility before returning success. Compare exact small CVRP instances and multiple starting points for nonconvex nonlinear problems. |
| A05 | **Cache replay changes pipeline semantics.** `pipelines/executor.py:130–177` records added or replaced artifact identities. A supported `FunctionStep` that mutates a dictionary in place stores no delta. The cold run produced `{'x': 2}`; the warm run produced `{'x': 1}` and reported a cache hit. Deletion also has no journal representation. Retries reuse the mutable context after a failed attempt. | Make cacheable steps return explicit artifact mutations or snapshot and journal values, including deletions. Publish cache records consistently after completion. Define retry isolation and test warm/cold downstream parity, mutation, deletion, failed attempts and concurrent writers. |
| A18 | **Container startup depends on the checkout's umask.** `docker/Dockerfile:53–65` copies the launcher and adds execute bits, then runs it under the unprivileged image user. From a 0600 checkout, the CA-enabled build succeeded, but the default entrypoint exited 126 with “Permission denied.” The interpreter also needs read access. Standalone UI mode inherits the API healthcheck on port 8000. Compose overrides the UI healthcheck. | Set the launcher mode explicitly to 0755, and use a mode-aware healthcheck or separate targets. Test builds from both restrictive and standard checkout umasks, direct API and UI startup, and Compose health. |

### P2 · Repair statistical interpretation and visibility

| ID | Evidence and consequence | Fix and acceptance test |
|---|---|---|
| A06 | **Diebold–Mariano reports a tie when losses differ on every point.** `forecasting/engine.py:101–115` maps any near-zero loss-difference variance to a tie with p = 1. With eight true zeros and prediction vectors of zeros versus ones, the mean loss difference is −1 with no sampling variance. | Distinguish exact equal loss from a nonzero constant difference. Retain deterministic loss preference and mark inferential statistics undefined for the degenerate case. Cover constant, nonfinite and dependent errors. |
| A07 | **Forecast inputs and reported coverage use incompatible assumptions.** `forecasting/engine.py:26–45,197–201` fills leading training gaps from the first future observation within training and replaces missing validation outcomes before scoring. A probe produced `[7, 7, 7, 8]` for `[NA, NA, 7, 8]`, so “past-only” applies to the validation boundary but fails within the training prefix. Scoring against imputed validation targets changes the estimand. | Trim leading gaps or require a documented prior value. Mask missing validation outcomes and report counts. Add leading-gap, missing-outcome and rolling-origin fixtures. |
| A08 | **Forecast champion and uncertainty labels overstate the tournament.** `forecasting/engine.py:245–271` makes an eligible non-baseline champion even if a baseline ranks first. The standard tournament constructs `FoundationForecaster()`, which defaults to local patch retrieval, and labels it `Foundation_ZeroShot`. Its default 0.1–0.9 bounds differ from the engine's default 95% level. Lines 309–338 transform component interval widths into directional normal deviations and reconstruct bounds. Even a mixture with known exact mean and variance need not have normal quantiles. | Let a valid baseline win or explicitly label the best non-baseline. Carry requested backend, actual backend, nominal quantiles and calibration provenance through API and UI. Compute mixture quantiles from samples/CDFs when available. Label moment-based intervals as approximations and measure out-of-sample coverage. |
| A09 | **Causal diagnostic confidence needs narrower language.** `mlops/root_cause.py:250–286` orients associations by onset, drift magnitude, names and even column order. It can propose hypotheses; observational ranking alone cannot establish an intervention effect. `causal/inference.py:183–240,521–566` implements 2×2 independent-cell DiD uncertainty and three one-draw refutation diagnostics with fixed tolerances. This does not establish parallel trends or account for repeated units and clusters. | Label inferred edges as hypotheses and record their evidence. Require explicit design metadata for confirmatory analyses. Support cluster-aware or panel inference where applicable, state assumptions, and test confounded nulls, repeated units, and outcome-unit rescaling. |
| A10 | **Visual fallback scores are called probabilities.** `models/computer_vision/foundation.py:247–284,328–341` softmaxes hand-weighted color/edge cues and exposes `probability`; detector fallback confidence is derived from region area. A black image with sole candidate “airplane” returns 1.0 on the local backend. The response discloses the backend, but the numeric field still implies a calibrated result. | Expose these values as heuristic scores and allow an unknown outcome. Require held-out calibration before making confidence claims. Test unrelated labels, abstention and explicit backend failures. |
| A11 | **Data quality accuracy is a proxy with a perfect default.** `data/quality.py:130–207` begins each column at 100 and lowers the value for numeric outliers and supplied ranges. A text-only dataset with no reference yields accuracy 100. This measures statistical plausibility and rule conformance, and omits correctness against trusted values. | Report rule conformance and plausibility separately from reference accuracy. Mark accuracy unavailable without reference data and publish the aggregation weights and denominator. Test a plausible dataset with systematically wrong ground truth. |
| A12 | **Selection disparity intervals have a post-selection interpretation problem.** `evaluation/fairness.py:137–176` chooses the empirically lowest and highest observed groups and builds ordinary two-group intervals. For more than two groups, the intervals omit the uncertainty of selecting extrema. Exact ties can select the same smallest group for both ends. Missing class denominators are already flagged elsewhere in the audited path. | Use distinct prespecified comparisons, or simultaneous/resampling intervals with a stated estimator. Test equal rates, unequal sizes, rare classes and repeated groups. Treat threshold passage as metric-specific evidence. |
| A13 | **Audit-state isolation is incomplete in test execution and error guidance.** `config/settings.py:13–22`, `tests/conftest.py` and `api/auth.py:46–56` leave the default audit path independent of the workspace path. A second run with fresh keys and only a new workspace directory failed collection with 20 audit MAC errors. Setting the audit-log path explicitly isolates the run. Rejection of mismatched state is appropriate. | Use independent key, workspace and audit paths together in test fixtures and startup docs. Improve diagnostics for mismatched signing keys, and exercise restart with the correct pair and recovery documentation for broken provenance. Keep fail-closed verification. |
| A14 | **CI coverage is shallower than the release and runtime claims.** `.github/workflows/ci.yml:53–106` tests lock installability and a limited import list, and runs fixture browser tests only. The live browser case is opt-in. The lock smoke does not prove freshness or that all declared extras were satisfied. The latency script measures small in-process fixtures and Python allocations, including a health request with no response assertion. Those measurements do not establish 60 fps, full RSS, or multi-tenant capacity. | Add real-backend Chromium to CI, assert actual response bodies in benchmarks, verify lock consistency against manifests, and publish a reproducible load protocol with datasets, concurrency, p95/p99, worker model, process RSS and frontend frame timing. |
| A15 | **Production image dependency selection floats.** `docker/Dockerfile:23–24` resolves optional extras and upgrades pip at build time. This gives the container a different dependency resolution from the hash-locked workflow documented in `README.md:110–124`. Build-to-build changes can alter behavior even with an unchanged application commit. | Lock the production image's exact extras and artifacts per supported target, verify hashes and build from that lock. Compare repeat image inventories and smoke API/UI startup against a pinned base digest. |
| A16 | **Forecast rolling-CV embargo misaligns prediction horizons.** `forecasting/engine.py:275–292` skips `gap` rows between training and evaluation, then asks for only the evaluation length and scores a forecast starting immediately after training. An exact linear forecaster reported RMSE 3.0 at gap 3, though its predictions at the correct timestamps would be exact. The separate backtesting engine already predicts through the gap and slices it off. | Reuse the alignment pattern from `evaluation/backtesting.py:52–60`. Define whether the final validation tail also observes the embargo, and assert timestamp and metric parity in a linear-series test. |
| A17 | **Carbon budget inputs are model estimates with incomplete attribution.** `core/carbon.py:33–41,101–133` uses assumed CPU/GPU watts, a RAM coefficient, country intensity and PUE. GPU power is added when CUDA is available even if a workload never uses it. The CodeCarbon branch estimates energy back from reported emissions using the local intensity. The executed notebook displayed zero emissions and a Green Score of 100 from disabled champion-fit tracking. `evaluation/model_cards.py:101–104,366` renders the numeric defaults without showing that measurement was disabled. | Label the estimation mode and assumptions alongside the budget, use backend-reported energy when available, and require workload device telemetry before attributing GPU use. Render disabled tracking as unmeasured in model cards. Validate idle, CPU-only and GPU cases against reference meters or telemetry. |
| A19 | **The SBOM provenance check validates only records the parser already recognizes.** `core/sbom.py:15–17,58–102,224–246` collects only exact-version pins, then checks those parsed records for hash presence. An unsupported or nonexact requirement form is outside the parsed package set and therefore outside the check. The generated BOM is a lockfile-derived inventory; it does not establish what was installed or authenticate package origin. | Report unrecognized non-comment records with line numbers, require a nonempty expected inventory per tier, and distinguish manifest syntax, artifact verification and deployed inventory. Compare the generated artifact against the actual container package inventory. |

### P3 · Correct precision and scope claims

- **KNN-Shapley complexity needs the query count.** `evaluation/robustness.py:345–380` sorts all training rows for each validation row and computes all feature distances. The advertised O(N log N) time describes one fixed-dimensional query. Give the full workload complexity and bound or batch it for large validations.
- **The user guide promises guarantees beyond the execution contract.** `docs/user_guide.md:148` promises zero leakage and production-ready deliverables from a workflow sequence. Group, time and target semantics still depend on the split, input provenance, and selected backend. Replace this with bounded claims and a route-to-test evidence matrix. Describe the default offline workflows alongside opt-in model downloads and remote integrations.
- **Synthetic domain examples, fallback implementations, and performance labels are distinct claims.** The repository labels many generators as synthetic and exposes backend identifiers in several paths. These are legitimate design choices. Demonstrations and backend probes provide weaker evidence than industry validation or measurement. Track claims such as “exact,” “calibrated,” “real-time,” and “enterprise-scale” against checked properties and versions.
